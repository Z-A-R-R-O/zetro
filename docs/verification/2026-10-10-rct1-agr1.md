## Admission Validates / Rejects

**Accepts:**
- Valid `rct.assignment.v1` manifests with canonical source root, exact read/write/create scope, data classification, check profiles, and resource ceilings
- Default budget values when budget field is omitted
- `createPaths` grants separate from write scope
- `internal` classification with explicit `allowRemoteInference: false`

**Rejects with explicit reason:**
- Wrong or missing `schemaVersion`
- Invalid `taskId` format
- Path traversal (`..`), hidden paths (`.secret`), backslashes, null bytes, colons, absolute paths
- Symlink/junction escape in writePaths or createPaths
- Missing checks or unsupported check profiles (only `equals`/`contains`)
- Check path outside declared scope
- `sensitive` classification with remote inference
- Non-public classification without explicit `allowRemoteInference` flag
- Filesystem root as `source.root`
- Out-of-range budget values
- Non-JSON or missing manifest files

## Known Limitations

1. **No glob expansion:** Scope paths are exact relative paths, not globs. This is intentional per RCT-PLAN §10 ("reject globs that expand after approval").
2. **Symlink detection requires accessible source root:** If the source root doesn't exist during dry-run, symlink checks are skipped (flagged as warning internally).
3. **No source hash recording during plan:** Source hashes are recorded during the Prepare stage (RCT-2), not during admission dry-run.
4. **Check profiles limited to `equals`/`contains`:** Named command profiles (e.g., test/lint/build) are deferred to RCT-2 per §10.
5. **No arbitrary shell command strings:** The admission module validates check types against a fixed allowlist. No shell string is accepted or emitted.

## Unresolved Decisions

1. **Data policy consent flow:** The plan command shows data classification and remote inference permission, but the interactive user consent prompt before actual execution is deferred to RCT-2.
2. **Provider/model validation during plan:** The manifest may declare a provider/model, but plan does not probe provider availability (that's `probe`'s job). Plan is strictly offline.
